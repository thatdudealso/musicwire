# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Runtime architecture and API contract are documented in `README.md`; configuration defaults are authoritative in `src/config.js`. Directory and registry listing status lives in `docs/launch-packet.md`. Remote MCP listings must use `POST https://musicwire.5432wire.com/mcp`, never the site root and never Smithery's proxy host.
- The independently publishable stdio MCP package is in `mcp/`; the same tools are served over Streamable HTTP at `POST /mcp` on the Express app (`mcp/src/http.js`, `mcp/src/server.js`). Stdio auto-pays a 402 when a buyer key is configured; the hosted endpoint never holds a wallet and returns the x402 `402` on unpaid `musicwire_validate` / `musicwire_render` calls. The server advertises tools plus empty `resources`/`prompts` catalogs (no invented content) and an empty Smithery `configSchema` (`musicwireMcpConfigSchema`, `GET /.well-known/mcp/server-card.json`, repo-root `smithery.yaml`). Smithery listing: `thatdudealso/musicwire`. Coverage: `test/mcp-e2e.test.js` (stdio stub payment, empty catalogs) and `test/mcp-http-e2e.test.js` (hosted initialize, tools/list, unpaid 402, server card).
- Static landing page and docs are served from `static/` directory by Express routes (`/` and `/docs`) with manifest-driven dynamic pricing. The public showcase catalog and self-hosted MP3s are in `static/examples/`; regenerate its MusicXML and `catalog.json` with `npm run examples:generate` (its output is Prettier-clean), and use `test/docs-examples-e2e.test.js` with `MUSICWIRE_E2E_EXAMPLES_OUTPUT_DIR=static/examples` to re-render the gallery through production QC.
- Run `npm test` for unit coverage; its `pretest` step installs `mcp/` dependencies, which `test/mcp-e2e.test.js` needs to spawn the MCP server. Set `MUSICWIRE_E2E=1` and `MSCORE_BIN` to run the real native MuseScore end-to-end test in `test/e2e.test.js`. `npm run test:x402-e2e` (`MUSICWIRE_X402_E2E=1`) runs the real Base Sepolia x402 buyer E2E in `test/x402-e2e.test.js`; it needs local CDP credentials and a funded test-USDC buyer, and it moves testnet funds.
- Run `npm run lint` (ESLint flat config) and `npm run format:check` (Prettier) before pushing; `npm run format` applies formatting.
- The Docker image is pinned to MuseScore Studio 4.7.2. Local ARM64 builds remain supported; production AMD64 images are built by GitHub Actions because local cross-architecture AppImage extraction is unreliable. Published-port container E2E is a deploy-phase follow-up because Docker Desktop reset loopback connections during the initial probe.
- Production infrastructure is defined in `infra/musicwire-production.yaml`; `.github/workflows/build-production-image.yml` publishes the immutable native AMD64 image to public `ghcr.io/thatdudealso/musicwire` with no AWS credentials, and `scripts/deploy-production.sh` deploys that image to on-demand ECS Fargate through the shared API Gateway VPC Link and internal NLB. An operator-pushed ECR image is the accepted fallback only if ECS cannot pull GHCR. Production artifacts are content-addressed S3 objects and the SQLite data directory is an EFS access point, preserving the `jobs`, `idempotency_keys`, `payment_wallets`, `payment_authorizations`, and `validate_results` tables across task replacement. WAL is unusable on that NFS mount, so `src/store.js` pins `journal_mode = TRUNCATE` with `synchronous = FULL`. This is deliberately a single-task service - both desired count and deployment maximum are 1 - so do not scale it without replacing SQLite-over-EFS with a multi-writer-safe store.
- Retention is asymmetric on purpose: the 30-day S3 lifecycle rule expires rendered artifact objects only, while job, payment wallet, payment authorization, and validation/settlement rows are kept indefinitely on EFS so artifact expiry can never destroy payment proof. `validate_results` is the only durable record of a paid validation, so never sweep it. `expireIdempotencyKeys()` deletes from `idempotency_keys` alone; do not extend it to any other table. Changing this retention or adding a privacy policy is a captain decision, not a maintenance change.
- Artifacts are delivered as a `302` to a short-lived presigned S3 URL issued only after `ArtifactStore.isValidToken` passes, which keeps the private bucket private and downloads clear of the API Gateway 10 MB payload quota. Do not restore inline proxying for S3 storage.
- x402 discovery ordering is deliberate: `POST /v1/validate` and `POST /v1/render` issue the 402 payment challenge before any payload validation (including malformed-JSON bodies, which reach the error middleware), so unpaid probes and directory crawlers always see the quote. Payload validation and its not-charged failure codes apply only once a `Payment-Signature` is presented. Do not reorder; regression coverage is in `test/payments.test.js`.
- x402 verify error handling is deliberate: the CDP facilitator answers `/verify` with HTTP 400 carrying an `{isValid:false, invalidReason}` body for determinate rejections, and `@x402/core` re-throws that as a `VerifyError`. `CdpX402Gateway.authorize` (`src/payment.js`) recovers a thrown `VerifyError` into the `isValid === false` re-challenge path so the buyer gets a `402` with the real reason (and the consumed-nonce replay branch stays reachable); only a genuinely indeterminate throw (network/timeout/5xx/credential) becomes `PaymentVerificationError` -> `503`, whose message must never assert the facilitator refused. Never restore a bare `catch` that flattens both into one facilitator-refused message; regression coverage is in `test/payments.test.js`.
- Artifact attribution is applied in `src/attribution.js` after QC, preserving notation and audio samples; signed hash receipts are durable in the SQLite `render_receipts` tables and publicly checked through `POST /v1/provenance/verify`. `ARTIFACT_SIGNING_SECRET` is domain-separated before receipt signing. Do not weaken the hash check to trust embedded metadata, because tags are intentionally detachable.
- Production boot is fail-closed on chain identity: `src/server.js` calls `verifyRpcNetwork` (`src/payment.js`) to confirm `eth_chainId` from `X402_RPC_URL` matches `X402_NETWORK` before binding a port. Keep that check ahead of `createApp()`.
